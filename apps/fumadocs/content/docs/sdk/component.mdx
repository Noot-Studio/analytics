The SDK ships several optional components:

- **`AnalyticsComponent`** ("Analytics Session Helper") — the zero-code entry point. It initializes the SDK core from its inspector fields and emits the default events that need a scene or network presence.
- **`AnalyticsMovementComponent`** ("Analytics Movement Tracker") — attach to a pawn to record its position as throttled, one-per-sample spatial events, feeding [voxel heatmaps](/docs/sdk/heatmap).
- **`AnalyticsDwellComponent`**, **`AnalyticsHeatmapComponent`**, **`AnalyticsTrajectoryComponent`** — the [aggregating spatial trackers](#aggregating-spatial-trackers). These accumulate on the client and flush a compact batch per window, so high-frequency position tracking stays affordable.

## Analytics Session Helper

### Add it to a scene

In the hierarchy panel, open the **Create** menu (the **+** button, or right-click) and choose **Analytics Helper**. This drops a prefab with the component attached. You can also add it to any existing GameObject via **Add Component**.

### Properties

Every field is exposed in the inspector.

| Field                  | Type     | Default                             | Purpose                                                                                                                             |
| ---------------------- | -------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `ApiKey`               | `string` | `""`                                | Your project's publishable `pk_…` key. Empty disables the SDK.                                                                      |
| `IngestUrl`            | `string` | `https://ingest.sbox-analytics.com` | Override for self-host / local dev.                                                                                                 |
| `TrackSessions`        | `bool`   | `true`                              | Emit `session_start` / `session_end`.                                                                                               |
| `TrackSceneLoads`      | `bool`   | `true`                              | Emit `scene_loaded` (and `map_loaded` once a map instance loads).                                                                   |
| `TrackConnections`     | `bool`   | `true`                              | Emit `player_connected` / `player_disconnected` (host only).                                                                        |
| `AutoScene`            | `bool`   | `true`                              | Tag every event with the active scene's title when no scene is passed explicitly.                                                   |
| `AutoPosition`         | `bool`   | `true`                              | Tag events with the player's pawn position when no position is passed explicitly. Events whose player has no pawn stay non-spatial. |
| `FlushIntervalSeconds` | `float`  | `10`                                | Background flush cadence in real seconds.                                                                                           |
| `MaxBatchSize`         | `int`    | `50`                                | Events per request. Clamped to the ingest cap (500).                                                                                |

### Events it emits

| Event                 | When                        | Notes                                               |
| --------------------- | --------------------------- | --------------------------------------------------- |
| `scene_loaded`        | On component start          | Carries the scene name. Gated on `TrackSceneLoads`. |
| `map_loaded`          | Once the map instance loads | Carries the map name. Gated on `TrackSceneLoads`.   |
| `player_connected`    | A player joins              | **Host only.** Gated on `TrackConnections`.         |
| `player_disconnected` | A player leaves             | **Host only.** Gated on `TrackConnections`.         |

`session_start` and `session_end` are owned by the core, not the component — they fire on init and shutdown when `TrackSessions` is on. See [Default events](/docs/sdk/events) for the complete list.

<Callout type="info">
  Connection events fire on the **host** only, since that's where the network
  listener lives. Clients won't emit `player_connected` / `player_disconnected`.
</Callout>

### Working alongside code

The component checks whether the core is already initialized before touching it:

- **Component initializes the core** — if you haven't called `Analytics.Init` yourself, the component does it from its fields and **owns the lifecycle**, calling `Shutdown()` (session_end + final flush) when it is destroyed.
- **Component attaches to an existing core** — if you already called `Analytics.Init` in code, the component skips init and just emits its scene/connection events. It does **not** shut the core down.

Pick one owner: either configure everything through the component, or `Init` in code and use the component only for its scene/connection events.

## Analytics Movement Tracker

Attach **`AnalyticsMovementComponent`** to an entity — typically a player pawn — to record its position as periodic spatial events. Those events feed the movement and traversal heatmaps in the [editor's Analytics dock](/docs/sdk/heatmap) and the dashboard.

Traffic is bounded by design: samples are throttled, stationary entities emit nothing, only the host samples by default, and events ride the SDK's existing batched flush — never one HTTP request per sample.

| Field                   | Type     | Default           | Purpose                                                                                              |
| ----------------------- | -------- | ----------------- | ---------------------------------------------------------------------------------------------------- |
| `EventType`             | `string` | `position_sample` | Event type recorded for each sample.                                                                 |
| `SampleIntervalSeconds` | `float`  | `2`               | Seconds between samples. Clamped to a 0.25 s minimum.                                                |
| `MinMoveDistance`       | `float`  | `64`              | Minimum distance (units) moved since the last sample. Stationary entities emit no events.            |
| `HostOnly`              | `bool`   | `true`            | Sample on the host only — one emitter per entity in multiplayer instead of one per connected client. |

Samples are attributed to the entity's network owner when it has one, so per-player movement lines up with the rest of that player's events. Unowned (world/NPC) entities fall back to the session's default id.

## Aggregating spatial trackers

The Movement Tracker emits **one event per sample**. At a useful sample rate that is thousands of events per player per minute — fine for occasional points (deaths, pickups), unaffordable for continuous tracking. The aggregating trackers fix this by **decoupling the event rate from the sample rate**: they sample fast but accumulate on the client and flush **one batch event per window**. A player standing still for five minutes becomes a single cell instead of hundreds of samples.

<Callout type="warn">
  These trackers are still **event-expensive** relative to ordinary events —
  they sample continuously. Each component shows a live `EstimatedEvents`
  estimate in the inspector and logs a warning on enable. Trajectories are the
  most expensive (they can't be aggregated); prefer Dwell or Heatmap unless you
  need exact paths.
</Callout>

### Dwell & Heatmap (cell aggregation)

Both quantize world position to a grid cell (`floor(pos / CellSize)`) and accumulate a per-cell metric, flushing a `spatial_cells` batch event. **Dwell** sums time-in-cell (milliseconds); **Heatmap** counts cell entries (visit density). The metric is tagged with a `kind` — `dwell` or `visits` — and the server sums it across windows and players. See [Spatial events](/docs/api/spatial#pre-aggregated-heatmaps).

| Field                  | Type    | Default | Purpose                                                                       |
| ---------------------- | ------- | ------- | ----------------------------------------------------------------------------- |
| `CellSize`             | `float` | `128`   | Edge length (units) of one cell. Bigger = coarser, fewer cells, fewer events. |
| `FlushIntervalSeconds` | `float` | `15`    | Seconds per window before flushing accumulated cells. Floored at 1 s.         |
| `MaxCellsPerFlush`     | `int`   | `256`   | Force an early flush once this many distinct cells are dirty, bounding size.  |
| `HostOnly`             | `bool`  | `true`  | Sample on the host only — one emitter per entity in multiplayer.              |

<Callout type="info">
  The capture grid is fixed at `CellSize`. The dashboard re-bins **coarser** (by
  summing whole multiples) but never finer — pick a `CellSize` at or below the
  finest resolution you'll want to view.
</Callout>

### Trajectory (per-player paths)

`AnalyticsTrajectoryComponent` records an entity's ordered path and flushes a `trajectory` batch event. It samples on an interval with a move-distance gate, then simplifies the buffered points with the **Ramer–Douglas–Peucker** algorithm before sending — dropping collinear points while keeping exact corner positions, so paths lose redundant points but no spatial precision.

| Field                   | Type    | Default | Purpose                                                                       |
| ----------------------- | ------- | ------- | ----------------------------------------------------------------------------- |
| `SampleIntervalSeconds` | `float` | `0.5`   | Seconds between path samples. Floored at 0.1 s.                               |
| `MinMoveDistance`       | `float` | `32`    | Minimum distance (units) moved since the last sample.                         |
| `FlushIntervalSeconds`  | `float` | `10`    | Seconds per window before simplifying and flushing.                           |
| `Epsilon`               | `float` | `32`    | RDP tolerance (units). Larger = more aggressive simplification, fewer points. |
| `HostOnly`              | `bool`  | `true`  | Sample on the host only.                                                      |

Trajectories keep player identity and order, so they **cannot be aggregated** like cells — they stay one row per kept point. Use them for replaying individual journeys; use Dwell/Heatmap for density across all players.
