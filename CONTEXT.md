# Domain Glossary

Canonical vocabulary for s&box Analytics. Use these terms in issue titles, test names, and proposals — don't drift to synonyms.

## Control plane (Postgres / Prisma)

| Term             | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Organization** | Top-level tenant. Owns projects, members, invitations, billing.                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Member**       | A user's membership in an organization, with a role: Owner, Admin, or Viewer.                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Invitation**   | A pending offer to join an organization with a given role.                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Project**      | A game (or one environment of a game) sending events. Belongs to one organization; identified by `slug` unique per org. Has an environment: Development, Staging, or Production.                                                                                                                                                                                                                                                                                                                                        |
| **API key**      | A key pair issued to a project. The **publishable key** (`pk_…`) is stored in plaintext and sent by game clients in the `X-Api-Key` header. The **secret key** (`sk_…`) is shown once and stored only as a hash. Keys are revoked, never deleted (`revokedAt`).                                                                                                                                                                                                                                                         |
| **Dashboard**    | A customizable grid of widgets. Scoped by `DashboardScope`: `OrgOverview`, `ProjectOverview`, or `CustomPage` (reserved, unused).                                                                                                                                                                                                                                                                                                                                                                                       |
| **Widget**       | A saved presentation template of a metric, owned by an organization: pairs a metric with a **visualization** (number, area, bar, table) that must be compatible with the metric's **result shape** (scalar, series, groups, grouped-series), plus view params (granularity, group-by, limit) and an optional project pin. Placed on dashboards as a `DashboardWidget` with free-form layout coordinates (`x`/`y`/`w`/`h`, react-grid-layout units; legacy `WidgetSize` retained for migration). Formerly called "card". |
| **Metric**       | A named, saved query definition owned by an organization. Stores a **query config** (the DSL: aggregation or expression, event type, filters) without `projectId`/`timeRange` — consumers supply those. Referenced by id from widgets and alert rules. Built-in widgets stay code-defined.                                                                                                                                                                                                                              |
| **Alert rule**   | A threshold watch on a metric: `operator` (Above/Below), `threshold`, `window` (LastHour/Last24Hours/Last7Days), delivery `channel` (Webhook/Email) + `destination`. Org-wide (`projectId` null) or per-project. **Fired** = threshold crossed; **notified** = fired and outside the 1-hour cooldown (`lastFiredAt`).                                                                                                                                                                                                   |
| **Query config** | The serializable value object inside a Metric (`metricConfigSchema` / `queryConfigSchema`). The metric builder's form and raw-JSON editor are two views of the same query config; raw SQL is never user-editable.                                                                                                                                                                                                                                                                                                       |

## Analytics plane (ClickHouse)

| Term                   | Definition                                                                                                                                                                                                                                                             |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Event**              | One row in `analytics.events`: `event_type`, `timestamp`, `session_id`, `player_id`, `properties`, optional `scene` + `position`. Ingested via `POST /v1/events` (batched).                                                                                            |
| **Core events**        | `session_start`, `session_end`, `player_death`, `level_complete`, `custom_event`.                                                                                                                                                                                      |
| **Performance events** | `fps_sample`, `crash`, `load_complete`.                                                                                                                                                                                                                                |
| **Session**            | The span between a `session_start` and its `session_end`, keyed by `session_id` (UUID generated by the client).                                                                                                                                                        |
| **Player**             | An anonymous participant, keyed by `player_id` — an anonymized hash. Never PII; never linked to a real identity.                                                                                                                                                       |
| **Spatial event**      | An event carrying `scene` + `position`, aggregated into **voxels** for in-world heatmaps. Read via `GET /v1/spatial/voxels` / `/v1/spatial/scenes` on ingest (secret-key auth); rendered in the dashboard and in the SDK's editor Analytics dock (fog or voxel cubes). |
| **Retention cohort**   | Players grouped by first-seen date (`analytics.player_first_seen`), measured at Day-1/7/30.                                                                                                                                                                            |
| **Funnel**             | An ordered sequence of event types players are expected to progress through.                                                                                                                                                                                           |
