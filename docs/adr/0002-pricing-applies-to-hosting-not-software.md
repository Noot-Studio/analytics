# Pricing applies to hosting, not software

The cloud offering is priced on infrastructure usage (monthly ingested event volume), never on product features. One codebase and one image serve both deployments: self-hosted runs fully featured with no plan tiers, feature gates, or license checks, while the cloud sets `BILLING_ENABLED=true` to activate quota enforcement at ingest. Two plans exist — Free (default event cap from `FREE_PLAN_MONTHLY_EVENT_LIMIT`) and Custom (an admin sets `Organization.eventLimit` manually after contact; there is no self-serve paid tier and therefore no payment integration). When an organization exceeds its quota, ingest soft-degrades: events are dropped with an explicit `quota_exceeded` response and the dashboard shows an upgrade banner — dashboard access is never locked and events are never silently sampled, since sampling corrupts analytics. Alternatives rejected: per-plan feature flags (creates fork pressure and hidden gates for self-hosted users), hard-locking over-quota orgs (punishes live games for their developer's billing state), and building Stripe/Polar now (premature while the only paid path is manual). Future plan work should extend the quota mechanism, not introduce feature gating.
