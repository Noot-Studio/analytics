# No generic async-render module for loading/error/empty states

The web app's loading/error/empty handling looks duplicated across views, tables, and dashboard cards, but it deliberately spans four incompatible mechanisms: analytics views interleave empty states _inside_ content rather than replacing it; `useFetchedTable` tables distinguish "no data at all" from "filters matched nothing"; dashboard cards delegate loading/error to Suspense + `CardErrorBoundary`; routes use TanStack Router `pendingComponent`/`errorComponent` slots. A shared `<DataRenderer>`/`useAsyncRender` module was prototyped on paper and rejected: it would be a pass-through whose props (`isLoading`, `isError`, `isEmpty`, `skeleton`, `error`, children-as-function) match or exceed the ~5 lines it replaces, and forcing one branch order would erase the filter-aware and interleaved-empty semantics or regress suspense cards to manual branching. Future architecture reviews should not re-suggest consolidating these branches.
